# Security Policy

## Reporting a vulnerability

Do not create a public issue for a suspected vulnerability, leaked credential, or weakness that could expose a system or data.

When GitHub Private Vulnerability Reporting is enabled for the repository, use its **Report a vulnerability** control. Until the project has published a dedicated security contact, maintainers should enable that GitHub feature before accepting public contributions.

Provide a minimal proof of concept, affected component and version, prerequisites, impact, and suggested mitigation. Remove customer data, credentials, tokens, and production URLs.

## Supported versions

During pre-1.0 development, the default branch is the supported version. Security fixes are delivered there first.

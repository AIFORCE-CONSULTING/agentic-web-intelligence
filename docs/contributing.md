# Contributing

## Before opening a change

1. Read the [project vision](foundation/project.md), [engineering principles](foundation/principles.md), and relevant [ADRs](decisions.md).
2. Keep changes focused and explain trade-offs.
3. Do not add credentials, production data, or unreviewed external tools.

## Quality expectations

- Format, lint, test, and build the affected component.
- Add or update documentation with behavior changes.
- Add an ADR for material architectural decisions.
- Preserve provenance when working with web-derived content.
- Design agent tools with least privilege and explicit failure behavior.

## Pull requests

Use the PR template, describe user impact, identify security implications, and include verification evidence.

# Data Model: Correct Report Exclusion Labels

## Report Exclusion

Represents one source disclosed in a stored report package because it did not
contribute to report findings.

**Canonical record:** `agentic_research_report_exclusions`

**Fields used by this feature:**

- `report_id`: Links the exclusion to one immutable stored report package.
- `source_url`: The candidate or evidence URL being disclosed.
- `source_title`: The operator-facing title available at report creation time.
- `topic_ids`: Planned topics assessed for this report.
- `reason_code`: Machine-readable explanation category.
- `reason`: Plain-language operator explanation.

**Reason code values for this feature:**

- `blocked_by_trust_policy`: The local trust workflow blocked the source.
- `review_required`: The source required human review and did not have a current acceptance.
- `access_denied_by_publisher`: The source or publisher rejected automated access before usable evidence was captured.
- `unreachable`: The platform could not capture usable evidence for a reason that is not classified as publisher access denial.
- `summary_failed`: The platform captured evidence but did not store a usable summary.
- `evidence_insufficient`: The platform captured content but it was insufficient for report findings.
- `not_relevant_to_planned_topics`: The platform had usable summarized evidence, but it did not qualify for any planned topic in the report.

**Validation rules:**

- `not_relevant_to_planned_topics` must not be used when preflight blocked or
  failed before usable evidence was captured.
- `not_relevant_to_planned_topics` must not be used for summary failures or
  evidence-insufficient summaries.
- Publisher access denial must not be labeled as local trust-policy blocking.
- The reason text must be generated by platform code, not model output.

## Source Preflight Outcome

Represents whether a discovered source could be checked, captured, and accepted
by the local trust workflow.

**Canonical records:** Existing research source/preflight fields.

**Fields read by this feature:**

- `preflight_status`
- `preflight_reason`
- `preflight_trust_disposition`
- `preflight_final_url`

**Relationship:** The exclusion builder reads these fields to decide whether a
source failed before summary/relevance decisions were possible.

## Summary Outcome

Represents whether captured evidence produced a usable stored source summary.

**Canonical records:** Existing evidence-summary execution source and artifact
records.

**Fields read by this feature:**

- summary execution source status
- failure category
- evidence sufficiency flag
- linked artifact existence

**Relationship:** Summary failure and evidence insufficiency override relevance
wording because they prevent the source from being qualified report evidence.

## Topic Relevance / Coverage Outcome

Represents whether a usable source summary counted toward a planned topic.

**Canonical records:** Existing topic relevance, coverage, and report-input records.

**Relationship:** A source may be labeled `not_relevant_to_planned_topics` only
after preflight and summary outcomes show that usable summarized evidence exists
and the source is absent from report inputs.
